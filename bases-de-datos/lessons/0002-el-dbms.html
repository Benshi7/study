Lección 02 · Unidad 1 · Sistemas de Gestión de Base de Datos

El DBMS por dentro: qué hace y quién lo usa

Base de datos y DBMS no son lo mismo, y en un parcial eso se nota enseguida. Uno son los datos; el otro es el software que los gobierna.

~8 minutos Elmasri & Navathe, cap. 1 Clase 1 de la cátedra

01La definición, y las cuatro funciones

"Un sistema de administración de datos (DBMS) es una colección de programas que permite a los usuarios crear y mantener una base de datos. El DBMS es un sistema de software de propósito general que facilita los procesos de definición, construcción, manipulación y compartición de bases de datos entre varios usuarios y aplicaciones."

Esas cuatro palabras del final son la respuesta completa a "¿qué hace un DBMS?". Memorizalas por lo que significan, no por la lista:

FunciónEn qué consisteCon qué se hace
Definir Especificar tipos de datos, estructuras y restricciones. DDL — CREATE TABLE
Construir Almacenar los datos en un medio controlado por el DBMS. Carga inicial, INSERT
Manipular Consultar, actualizar para reflejar cambios del minimundo, generar informes. DML — SELECT, UPDATE
Compartir Permitir que varios usuarios y programas accedan a la vez. Transacciones, bloqueos

Y hay dos funciones más que Elmasri agrega aparte, porque no son de uso diario sino de supervivencia: protección (contra caídas de hardware o software, y contra accesos no autorizados) y mantenimiento a lo largo de un ciclo de vida que puede durar años, dejando evolucionar el sistema cuando cambian los requisitos.

Error de definición

"Una base de datos es un programa donde guardo información" es falso, y es la respuesta que más se escribe en los parciales. La base de datos son los datos. El DBMS es el software. Al conjunto de los dos — más las aplicaciones que los usan — se lo llama sistema de bases de datos.

02El catálogo: por qué el DBMS es autodescriptivo

Esta es la característica que de verdad separa un DBMS de un montón de archivos, y la que menos se entiende. Un sistema de bases de datos no contiene sólo la base: contiene además una descripción completa de su propia estructura.

Esa descripción vive en el catálogo, y su contenido se llama metadatos: qué tablas hay, qué columnas tiene cada una, de qué tipo, con qué restricciones.

Por qué importa

El software del DBMS no fue escrito para tu base. Es de propósito general: el mismo Oracle corre la base de una universidad, la de un banco y la de una farmacia. Puede hacerlo porque, cada vez que necesita saber algo sobre la estructura, lo consulta en el catálogo en lugar de tenerlo escrito adentro.

Compará con el mundo de archivos: ahí la estructura del archivo — y en el caso extremo hasta la posición exacta de un campo dentro del registro — está codificada dentro de cada programa que lo abre. De ahí sale la propiedad que da nombre a la siguiente clase: la independencia programa–datos.

03Las cuatro características del enfoque de bases de datos

Elmasri las lista juntas, y es una lista que se pregunta tal cual. Tres de las cuatro ya aparecieron; la tercera es la que se desarrolla en la lección 3.

  1. Naturaleza autodescriptiva — el catálogo y los metadatos.
  2. Aislamiento entre programas y datos, y abstracción de datos.
  3. Soporte de varias vistas de los datos — cada grupo de usuarios ve su recorte.
  4. Compartición de datos y procesamiento de transacciones multiusuario.

04Quiénes usan la base

El temario pide "usuarios de la base de datos" como tema propio. No es relleno: cada tipo de usuario justifica una parte distinta del sistema.

UsuarioQué hace
DBA (administrador) Autoriza accesos, controla el uso, consigue recursos, atiende el rendimiento y la seguridad. Es quien responde cuando la base se cae.
Diseñador Releva requisitos con los usuarios, identifica los datos y elige las estructuras. Es el rol que estás aprendiendo a ocupar en la Unidad 2.
Usuario final Consulta y actualiza. Se subdivide en casuales (consultas distintas cada vez), paramétricos (siempre la misma operación, por ejemplo un cajero) y sofisticados (analistas, que escriben sus propias consultas complejas).
Analista de sistemas y programador Construye las aplicaciones que hablan con el DBMS.
