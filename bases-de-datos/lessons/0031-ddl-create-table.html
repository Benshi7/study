CREATE TABLE, y las seis restricciones

Esto ya lo tomaron

El modelo de examen que circula (Examen1) pregunta textual: "Nombre y explique 3 Restricciones (Constraints)". Al final de esta lección tenés que poder nombrar las seis y explicar cualquiera en dos renglones.

01Qué crea el DDL

El deck abre con una definición: el DDL "se encarga de la creación y modificación de la estructura de los objetos de la base de datos". Los tres comandos son CREATE, ALTER y DROP. Esta lección cubre el primero; los otros dos están en la 0038. Los objetos básicos son cuatro:

ObjetoQué es, según el deck
TablaUnidad básica de almacenamiento. La representación física de las entidades.
VistaRepresentación lógica de un subconjunto de datos de una o más tablas.
ÍndiceEstructura asociada a la tabla para que las consultas rindan más (0028).
RestricciónFuerza condiciones (reglas de negocio) sobre los registros. La representación física de las relaciones.

La última frase es la que conecta todo el cuatrimestre: el rombo del DER se convierte en una FK, y la FK es una restricción. Lo que dibujaste en el DER, el motor lo hace cumplir acá.

02La forma de la sentencia

CREATE TABLE NOMBRE_TABLA (
  nombre_campo  tipo(extensión)  NULL | NOT NULL  restricción,
  ...
);

Los tipos que lista el deck: CHAR(n) (largo fijo), VARCHAR(n) (largo variable), INT/SMALLINT, FLOAT/REAL (aproximado), DECIMAL/NUMERIC (precisión fija), DATETIME. Para plata o medidas, DECIMAL: el FLOAT redondea.

Si no ponés nada, acepta NULL

"Si no especifica NULL o NOT NULL, se utiliza el valor predeterminado, el cuál es que las columnas se creen con la opción NULL." Olvidarse el NOT NULL no da error: deja pasar datos vacíos sin avisar.

03Las seis restricciones

El deck las enumera en este orden. Antes de abrir cada una, intentá decir qué fuerza:

PRIMARY KEY

Fuerza la unicidad del conjunto de columnas que identifica cada registro. Lleva implícito el NOT NULL. Se declara a nivel de columna si es simple (codigo INT PRIMARY KEY) o a nivel de tabla, que sirve también para las compuestas: CONSTRAINT pk_curso PRIMARY KEY (codigo_curso, codigo_categoria).

UNIQUE

Fuerza la unicidad de una columna que no es la PK. Es la forma de declarar una clave candidata (0005): en la Clínica, la habitación se identifica por Cod_Habitacion, pero (Cod_Torre, Piso, Numero) tampoco puede repetirse.

DEFAULT

Fuerza un valor predeterminado cuando el INSERT no trae esa columna. Cant_Banios INT NOT NULL DEFAULT 1.

NOT NULL

Fuerza la existencia de valor: cada fila tiene que traer esa columna completa.

CHECK

Restringe el dominio: una condición que toda fila debe cumplir. CHECK (Cant_Camas > 0), CHECK (Posee_Ventana IN ('S','N')). Ojo con la tabla de evaluación del deck, abajo.

FOREIGN KEY

Fuerza la integridad referencial: el valor tiene que existir como PK en la tabla padre, o ser NULL. Establece la jerarquía padre–hijo. FOREIGN KEY (Cod_Torre) REFERENCES TORRE (Cod_Torre). El ON DELETE se ve en la 0038.

CHECK con un NULL: pasa

El deck lo tabula: si la condición da FALSO, error. Si da VERDADERO, pasa. Y si da DESCONOCIDO, porque el campo es NULL, también pasa. CHECK (Cant_Camas > 0) no impide un Cant_Camas nulo: para eso hace falta además el NOT NULL.
