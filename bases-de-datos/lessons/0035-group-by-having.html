Agregar, agrupar, y filtrar grupos

Las funciones agregadas convierten muchas filas en un número. GROUP BY decide cuántos números sacás, y HAVING filtra después de calcularlos.

~15 minutos Deck "DML", slides 15–24 Prioridad para el 2do parcial: muy alta

01Las cinco funciones

SUM(), COUNT(), AVG(), MIN(), MAX(). Sin GROUP BY, toda la tabla es un grupo y el resultado es una sola fila. 

SELECT COUNT(*) AS Cantidad_Habitaciones
FROM   HABITACION
WHERE  Cod_Torre = 1;
COUNT(*) no es COUNT(columna)

El deck lo dice: COUNT cuenta "el número de filas de una tabla o el número de valores no nulos de una columna". COUNT(*) cuenta filas. COUNT(Cod_Prepaga) salta los NULL: en PACIENTE da 8, no 10. Y COUNT(DISTINCT Cod_Prepaga) da 3: cuántas prepagas distintas se usan.

02GROUP BY: una fila por grupo

SELECT   S.Nombre, COUNT(*) AS Consultas
FROM     HISTORIA_CLINICA H
JOIN     SERVICIO S ON S.Cod_Servicio = H.Cod_Servicio
GROUP BY S.Nombre;
La regla del SELECT agrupado

Con GROUP BY, cada columna del SELECT tiene que estar en el GROUP BY o adentro de una función agregada. Si pedís H.Fecha sin agruparla, ¿cuál de todas las fechas del grupo mostraría el motor? Los motores estrictos dan error. SQLite elige una cualquiera, y eso es peor.

03WHERE filtra filas; HAVING filtra grupos

"La cláusula HAVING especifica una condición de búsqueda para los grupos seleccionados por la cláusula GROUP BY." El orden real de ejecución explica la diferencia:

  1. FROM y los JOIN arman las filas.
  2. WHERE descarta filas. Todavía no hay grupos, así que acá no se puede usar COUNT.
  3. GROUP BY arma los grupos y calcula las agregadas.
  4. HAVING descarta grupos, mirando esos totales.
  5. SELECT proyecta y ORDER BY ordena.
