OLTP, OLAP y qué es un Data Warehouse

La base que registra las operaciones del día no sirve para analizar el negocio. El Data Warehouse existe para eso, y la inteligencia de negocios (BI) se apoya en él.

~20 minutos Deck "Intro Datawarehouse", slides 13–21 y 44–52 Prioridad para el 2do parcial: alta (teoría choice)

Qué tomar de esta lección

01Business Intelligence: qué no es

"BI no es: una marca, un producto, un sistema, una base de datos, una empresa, una ciencia… Es mejor pensar que BI está más vinculado a una arquitectura, una colección integrada de datos operacionales, una serie de aplicaciones para la toma de decisión y bases de datos que, en su conjunto y a través de técnicas específicas, proveen a una comunidad de usuarios un fácil acceso a datos de negocio. BI no se compra, se construye."

Sus características, según el deck: accesibilidad a datos e información, apoyo en la toma de decisiones y orientación al usuario final. Por técnicas y salidas, se categoriza en cuatro:

  • Consultas e informes (queries, reporting, charting).
  • Análisis OLAP (On Line Analytical Processing).
  • Analytics: data mining, text mining, advanced analytics.
  • Sistemas de previsión empresarial: forecasting, análisis predictivo.

Las herramientas de BI no leen las tablas crudas: acceden a una capa lógica hecha de vistas que se adapta a cada organización. El deck lo muestra con una vista Clientes que renombra campos y agrega un indicador CASE WHEN … THEN 'Propio' ELSE 'Externo' END AS Ind_Staff: la misma técnica de la lección 0039 y de la 0052.

02El Data Warehouse

El deck da varias definiciones y cierra con "Varios… Muchos". Las tres que muestra:

"Un Data Warehouse (DW) es un almacén o repositorio de datos categorizados, que concentra un gran volumen de información de interés para toda una organización, la cual se distribuye por medio de diversas herramientas de consulta y de creación de informes orientadas a la toma de decisiones."
"Es una copia de datos transaccionales específicamente estructurados para consultas y reportes" (Ralph Kimball).
"Es una vista consolidada de datos corporativos optimizados para reportes y análisis: copia sumarizada de transacciones y datos no transaccionales específicamente estructurados para consultas y análisis."

Las cinco características

El slide 21 lo resume como una lista. "El DW es":

CaracterísticaQué significa
Colección de datosRepositorio de datos categorizados, no un programa.
Orientado a temas / focoSe organiza por temas del negocio (ventas, clientes…) y no por aplicación.
IntegradoReúne datos de varias fuentes en una sola visión homogénea.
Variante en el tiempoLos datos llevan tiempo: se guarda cómo eran en cada momento. Acá entra la 0052.
No volátil / históricoLos datos se cargan y se consultan; no se modifican ni se borran como en una base operativa.

El deck sólo enumera las cinco; la columna de la derecha es la explicación habitual de cada una.

El deck lo plantea como primera solución a viejos problemas: las preguntas de la dirección ("¿cuánto vendimos por región y por mes?") eran difíciles de responder con los sistemas operativos. El DW pretende "dar un soporte a la organización para proporcionarle una buena gestión de sus datos, que le ayude en la toma de decisiones estratégicas / tácticas".

03OLTP contra OLAP

OLTPOLAP
SiglaOn-Line Transactional ProcessingOn-Line Analytical Processing
Para quéEjecutar transacciones (banca en línea, compras, entrada de pedidos, mensajes de texto)Análisis multidimensional: tendencias de ventas, patrones de consumo, informes complejos
OperacionesMuchas transacciones simples: inserciones, actualizaciones y eliminacionesLectura de grandes volúmenes de datos para extraer información útil
VelocidadRespuesta en milisegundosAlta velocidad sobre grandes volúmenes
Disponibilidad24 horas, 7 días, con copias de seguridad incrementales constantes—
De dónde vienen los datosSe generan ahí, por los empleados de front-end y los clientesProvienen de un data mart, un almacén de datos centralizado o un data warehouse

"Los sistemas OLTP están diseñados para la superioridad de las transacciones en lugar del análisis de datos."

04El cubo OLAP

"Cubo (OLAP): información pre-agregada con todas las combinaciones posibles de las perspectivas incluidas, y de esta forma visualizar las métricas que le interesen al usuario."

Las estructuras multidimensionales están compuestas por dimensiones y métricas. Las dimensiones, a su vez, tienen jerarquías y niveles: en la dimensión geográfica, el nivel más alto son los continentes, luego los países, los estados y, el más bajo, los municipios. El cubo del deck cruza clientes × productos × fechas y responde cosas como "¿cuántas muñecas se vendieron en total a Toyland?".

05MOLAP, ROLAP y HOLAP

Tres formas de guardar los datos de un sistema OLAP:

ModeloDónde están los datosVentajasDesventajas
MOLAP En una estructura multidimensional. El resumen se calcula por adelantado (agregaciones precalculadas), con técnicas de compresión. Mayor desempeño en las consultas · puede escribir sobre las bases de datos · permite cálculos más complicados Tamaño limitado para la arquitectura del cubo · no se accede a los datos que están en el cubo · no se explota el paralelismo de las bases de datos
ROLAP En una base de datos relacional: datos detallados, sin agregaciones, tablas normalizadas. Esquemas estrella o copo de nieve. Usa toda la seguridad e integridad de la base · escalable a grandes volúmenes · datos compartidos con aplicaciones de consulta (SQL) · estructuras más dinámicas Consultas más lentas · construcción cara · los cálculos se limitan a las funciones de la base de datos
HOLAP
híbrido		 El detalle en la base relacional y los datos resumidos o agregados en una base multidimensional separada. Toma un poco de cada uno.

Cuándo conviene cuál

  • Volatilidad: si cambian las reglas de agregación, ROLAP hace la consolidación ad-hoc; MOLAP está pensado para consolidaciones batch (precompiladas).
  • Dimensiones: ROLAP crece a muchísimas; MOLAP anda bien con diez o menos.
  • Volumen: ROLAP soporta grandes volúmenes de datos elementales; MOLAP se comporta bien con volúmenes reducidos (menos de 5 Gb).
  • Alcance: ROLAP es una arquitectura flexible y general; MOLAP es una solución particular, de nivel departamental.
