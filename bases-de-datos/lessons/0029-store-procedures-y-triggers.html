Store procedures y triggers: código que vive en el motor

Un procedimiento se ejecuta cuando alguien lo llama. Un trigger, cuando pasa algo en una tabla. Esa es toda la diferencia, y lo primero que hay que poder decir.

01Store procedures

"Un conjunto de instrucciones destinados a ejecutar un proceso específico. Pueden aceptar parámetros de entrada y salida, y pueden devolver ya sea un valor o un conjunto de registros." Su razón de ser, según el deck: encadenar procesos dentro del servidor en lugar de ir y volver entre cliente y servidor por cada paso, lo que "conlleva a un mayor tráfico de datos y tiempo".

Las tres circunstancias en que son útiles (slide 18, textual de Elmasri §9.4.1):

  1. Si varias aplicaciones necesitan el mismo programa: se guarda en el servidor y todas lo invocan. Menos duplicación, más modularidad.
  2. Ejecutar en el servidor reduce el costo de transferencia y comunicación entre cliente y servidor.
  3. Mejoran la potencia de modelado de las vistas, permitiendo tipos más complejos de datos derivados.

Se ejecuta con CALL nombre_procedimiento(argumentos);.

El procedimiento del examen, línea por línea

CREATE PROCEDURE Desa_ETL_ADMIN.GET_LOAD_ID(IN DTS_Package_Name VARCHAR(250), OUT Load_id INTEGER)
BEGIN
  DECLARE FECHA DATE;
  DECLARE HORA INTEGER;
  SELECT DATE INTO :FECHA;
  SELECT TIME INTO :HORA;
  INSERT INTO Desa_ETL_ADMIN.LOAD_INSTANCE_LOG (DTS_Package_Name, Load_Start_Dt, Load_Start_Tm)
    VALUES (:DTS_Package_Name, :FECHA, :HORA);
  SELECT Load_Id INTO :Load_Id
  FROM   Desa_ETL_ADMIN.LOAD_INSTANCE_LOG
  WHERE  DTS_Package_Name = :DTS_Package_Name
    AND  Load_Start_Dt = :FECHA AND Load_Start_Tm = :HORA;
END;

Respuesta modelo — qué hace GET_LOAD_ID

Es un procedimiento del esquema Desa_ETL_ADMIN (desarrollo) que registra el inicio de una carga y devuelve el identificador que le asignó la base.

  1. Recibe un parámetro de entrada, el nombre del paquete de carga (DTS_Package_Name), y tiene uno de salida, Load_id.
  2. Declara dos variables locales y guarda en ellas la fecha y la hora actuales.
  3. Inserta una fila en la tabla de log LOAD_INSTANCE_LOG con el nombre del paquete, la fecha y la hora de inicio. El Load_Id no se inserta: lo genera la tabla (es autonumérico).
  4. Busca esa misma fila (por paquete, fecha y hora) y copia su Load_Id en el parámetro de salida.

Quien lo llama, con CALL Desa_ETL_ADMIN.GET_LOAD_ID('P_LDM_AGMT_DAILY_SALES', Load_Id);, obtiene el número de carga (en el slide 20, 10100009) y lo usa para marcar las filas que esa carga inserte. Es lo que se ve en la columna Load_Id de la tabla Postal_Code del slide 20.

02Triggers

"Los disparadores se encargan de activar una determinada función cuando ocurre un cierto evento ya sea en una tabla o una vista." El evento es siempre una sentencia DML: INSERT, UPDATE o DELETE. "Se utilizan para ejecutar reglas de negocio en los datos, auditar o validar datos." Elmasri los llama reglas ECA: Evento, Condición, Acción.

MomentoSegún el deck
BEFORESólo en tablas, antes de verificar las restricciones. Sirve para chequear reglas que no se pueden expresar con referencias.
AFTERSólo en tablas, después de la operación. Se usa para propagar cambios a otras tablas en cascada.
INSTEAD OFEn vistas, para hacerlas actualizables.

El ejemplo del slide 23, que es el de Elmasri (en el deck salió con errores de OCR: "IN5ERT", "15 NOT NULL"):

CREATE TRIGGER SueldoTotal1
AFTER INSERT ON EMPLEADO                -- evento
FOR EACH ROW
WHEN (NEW.Dno IS NOT NULL)               -- condición
  UPDATE DEPARTAMENTO                    -- acción
  SET    SueldoTotal = SueldoTotal + NEW.Sueldo
  WHERE  Dno = NEW.Dno;

NEW es la fila que se acaba de insertar (en un UPDATE o un DELETE existe también OLD, la fila de antes). FOR EACH ROW hace que la acción corra una vez por fila afectada.

Respuesta modelo — pregunta 2 (qué es un trigger y un ejemplo)

Un trigger es un objeto de la base que ejecuta automáticamente una acción cuando ocurre un evento DML (INSERT, UPDATE o DELETE) sobre una tabla o vista. Se define con un momento (BEFORE, AFTER o INSTEAD OF), una condición opcional y una acción. Se usa para reglas de negocio, auditoría y validación.

Ejemplo: en la Clínica, un trigger AFTER INSERT sobre OCUPACION que incrementa el contador de camas ocupadas de la habitación. O uno BEFORE INSERT que rechaza una internación si la habitación ya no tiene camas libres, una regla que una FK o un CHECK no pueden expresar.

Respuesta modelo — pregunta 5 (store procedure)

Un store procedure es un conjunto de instrucciones guardado en el servidor de base de datos, que ejecuta un proceso específico; puede recibir parámetros de entrada y salida y devolver un valor o un conjunto de registros. Lo usaría cuando varias aplicaciones necesitan el mismo proceso, o para encadenar varios pasos dentro del servidor y ahorrar el ida y vuelta con el cliente. Se llama con CALL nombre(argumentos);.

SP vs trigger en una línea

Al procedimiento lo llama alguien (CALL). El trigger se dispara solo, por un evento DML. Un trigger no recibe parámetros: recibe NEW y OLD.
