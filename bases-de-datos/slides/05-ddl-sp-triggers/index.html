1 · CREATE TABLE

Cada columna se declara en cuatro partes

Ojo en el choice

Si no ponés NULL ni NOT NULL, el valor por defecto es que la columna acepta nulos. NOT NULL obliga a que cada fila tenga un valor en esa columna.

2 · Restricciones

Seis restricciones, seis cosas que se fuerzan

PRIMARY KEY

Unicidad del conjunto de columnas que identifica cada fila.

UNIQUE

Unicidad de una columna que no es la clave.

DEFAULT

Un valor predeterminado si no se carga ninguno.

NOT NULL

Que el valor exista.

CHECK

Restringir el dominio: una condición que toda fila cumple.

FOREIGN KEY

Integridad referencial: jerarquía padre-hijo entre tablas.

En criollo

Las restricciones son parte de la definición de la tabla. La base rechaza cualquier INSERT o UPDATE que las viole: las reglas no dependen de que la aplicación se acuerde de validarlas.

2 · Restricciones

PRIMARY KEY: a nivel de columna o de tabla

A nivel de columna · sólo clave simple

CREATE TABLE Curso (
  codigo_curso int PRIMARY KEY,
  nombre       char(40) NOT NULL
);

A nivel de tabla · simple o compuesta

CREATE TABLE Curso (
  codigo_curso     int,
  codigo_categoria int,
  nombre           char(40) NOT NULL,
  CONSTRAINT pk_curso
    PRIMARY KEY (codigo_curso, codigo_categoria)
);
En criollo

Si la clave tiene dos o más columnas, sólo se puede declarar a nivel de tabla. A nivel de tabla, además, le ponés nombre a la restricción (pk_curso), y eso te deja borrarla después con ALTER … DROP CONSTRAINT.

Ojo

La PK ya implica NOT NULL. El deck dice que declarar las dos cosas da error; en SQLite lo probamos y se acepta. En la hoja, seguí al deck y no las declares juntas.

2 · Restricciones

FOREIGN KEY: el hijo sólo puede apuntar a padres que existen

Los campos referenciados del padre tienen que ser su clave primaria; si no, la restricción no se puede crear.

CONSTRAINT fk_curso_cat
  FOREIGN KEY (codigo_categoria)
  REFERENCES Categoria (id)
  [ON DELETE {CASCADE | SET NULL}]

Los valores de las tablas son un ejemplo nuestro.

2 · Restricciones

ON DELETE: qué pasa con los hijos si borro al padre

En criollo

ON DELETE no es obligatorio. Si no lo ponés, el motor valida que no haya hijos y, si los hay, rechaza el borrado. Lo probamos en SQLite: los tres casos se comportan así.

2 · Restricciones

CHECK: una condición que cada fila tiene que cumplir

A nivel de columna

duracion int CHECK (duracion > 0)

A nivel de tabla, con nombre

CONSTRAINT ck_curso_duracion
  CHECK (duracion > 0)

Cómo resuelve el motor cada alta o cambio

La condición da…Resultado
Falso (−1)viola · error
Verdadero (5)no viola · ok
Desconocido (NULL)no viola · ok
Ojo

Un NULL pasa el CHECK: NULL > 0 es desconocido, y desconocido no viola. Si el campo no puede quedar vacío, además va NOT NULL. Es la trampa del ejercicio 3 de la lección 0031.

3 · ALTER y DROP

ALTER: cambiar la estructura de algo que ya existe

AcciónObjetoSintaxis
AgregarColumnaALTER TABLE Curso ADD comentario char(40)

En criollo

Con ALTER se agregan, quitan o modifican columnas, índices y restricciones sin borrar la tabla ni sus datos. Para borrar una restricción hace falta su nombre: por eso conviene nombrarlas con CONSTRAINT.

3 · ALTER y DROP

DROP borra el objeto entero; DELETE, sólo filas

DDL · el objeto

DROP TABLE Curso

Desaparece la tabla: estructura y datos.

DDL · una columna

ALTER … DROP COLUMN

ALTER TABLE Curso DROP COLUMN Curso_Nombre: la tabla queda, sin esa columna.

DML · los datos

DELETE FROM Curso

Borra filas; la tabla vacía sigue existiendo.

Ojo en el choice

DROP es DDL (estructura); DELETE es DML (datos). Un DELETE sin WHERE deja la tabla vacía; un DROP la hace desaparecer.

4 · Stored procedures

Stored procedure: un proceso que vive en el servidor

  • Un conjunto de instrucciones para un proceso específico. Acepta parámetros de entrada y salida y puede devolver un valor o un conjunto de registros.
  • Sirve cuando varias aplicaciones necesitan el mismo programa (menos duplicación, más modularidad), para reducir la comunicación cliente-servidor y para dar tipos de datos derivados más complejos que una vista.

4 · Stored procedures

El ejemplo del deck: GET_LOAD_ID

CREATE PROCEDURE Desa_ETL_ADMIN.GET_LOAD_ID(
    IN  DTS_Package_Name VARCHAR(250),
    OUT Load_Id INTEGER)
BEGIN
  DECLARE FECHA DATE;
  DECLARE HORA INTEGER;
  SELECT DATE INTO :FECHA;
  SELECT TIME INTO :HORA;
  INSERT INTO Desa_ETL_ADMIN.LOAD_INSTANCE_LOG
    (DTS_Package_Name, Load_Start_Dt, Load_Start_Tm)
  VALUES (:DTS_Package_Name, :FECHA, :HORA);
  SELECT Load_Id INTO :Load_Id
  FROM Desa_ETL_ADMIN.LOAD_INSTANCE_LOG
  WHERE DTS_Package_Name = :DTS_Package_Name
    AND Load_Start_Dt = :FECHA AND Load_Start_Tm = :HORA;
END;

Qué hace

  1. Recibe el nombre del paquete de carga (IN).
  2. Toma la fecha y la hora.
  3. Registra el inicio de la carga en un log.
  4. Devuelve el Load_Id generado (OUT).
CALL Desa_ETL_ADMIN.GET_LOAD_ID(
  'P_LDM_AGMT_DAILY_SALES', Load_Id);
-- Load_Id = 10100009

Sintaxis de Teradata. Para ver el código de un SP: SHOW PROCEDURE nombre. El Load_Id es el mismo campo “identificador de carga” del TP de SCD.

5 · Triggers

Trigger: código que se dispara solo ante un cambio

  • Activa una función cuando ocurre un evento sobre una tabla o una vista: cualquier sentencia DML que modifique datos.
  • Se usa para ejecutar reglas de negocio, auditar o validar datos.
Ojo en el choice

BEFORE y AFTER: sólo en tablas. INSTEAD OF: en vistas. Un trigger no se llama: se dispara solo. Un SP se ejecuta con CALL.

5 · Triggers

El ejemplo del deck: mantener el sueldo total del departamento

CREATE TRIGGER SueldoTotal1
AFTER INSERT ON EMPLEADO
FOR EACH ROW
WHEN (NEW.Dno IS NOT NULL)
  UPDATE DEPARTAMENTO
  SET SueldoTotal = SueldoTotal + NEW.Sueldo
  WHERE Dno = NEW.Dno;
En criollo

NEW es la fila recién insertada. La condición evita tocar departamentos cuando el empleado no tiene uno. La acción del trigger es un evento sobre otra tabla: por eso es AFTER. (Los números del dibujo son un ejemplo; el PPT trae este código con errores de tipeo, “IN5ERT” y “15 NOT NULL”, que acá corregimos.)

Los de la PK del padre, más NULL.

Se borran también los hijos.

Sí: desconocido no viola la restricción.
