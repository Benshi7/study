Respuesta 2 · teoría

Los tres índices, con un ejemplo sobre la misma tabla

Un índice es una estructura que mapea valores de columnas a filas para evitar la búsqueda secuencial. Ejemplo: CabeceraFact (NFact, Fecha, CodCli).

TipoQué esBeneficio · costoEjemplo
PrincipalSobre la clave primaria. Uno solo por tabla.Unicidad, búsqueda por clave, base de la integridad referencialSobre NFact: “la factura 4318”
AgrupadoLas filas se guardan en el mismo orden que el índice: ordena físicamente.Búsqueda eficiente, ahorro de espacio · limita las modificacionesSobre CodCli: las facturas de un cliente, juntas
SecundarioSobre columnas que no son la PK. Estructura aparte.No toca el orden, flexible · más espacio; demasiados degradanSobre Fecha: “las facturas de enero”
Lo que más se toma

“¿Cuál ordena físicamente? Justifique.” → el agrupado, porque “las filas de la tabla se ordenan en el mismo orden que el índice” y quedan “físicamente almacenadas juntas en el disco”. Y el error que el profe marca siempre: no acordarse para qué sirve cada uno.

Pregunta 3 · teoría

“Explique para qué sirve la instrucción EXISTS de SQL. Dé un ejemplo.”

Intentalo en papel · 5 minutos

Pista: qué comprueba, cuándo da verdadero y qué lo diferencia de IN.

Respuesta 3 · teoría

EXISTS comprueba si una subconsulta devuelve filas

Comprueba la existencia de filas: es verdadero sólo si la subconsulta devuelve al menos una. Se usa sólo con subconsultas; IN, en cambio, acepta subconsultas y listas de valores.

Ejemplo con las tablas del parcial

Proveedores que enviaron algún componente rojo:

SELECT P.PNOMBRE FROM PROVEEDORES P
WHERE EXISTS (
  SELECT * FROM ENVIOS E
  JOIN COMPONENTES C ON C.C = E.C
  WHERE E.P = P.P AND C.COLOR = 'ROJO');
Proveedor¿Existe un envío rojo suyo?
CARLOSsí → entra
JUANno → queda afuera
JOSEsí → entra
INMAsí → entra
EVAsí → entra

Con NOT EXISTS queda sólo JUAN: el que no envió ninguno.

En criollo

La subconsulta mira la fila de afuera (E.P = P.P): para cada proveedor pregunta “¿hay al menos uno?”. No importa qué devuelve, sólo si devuelve algo; por eso es costumbre poner SELECT *.

Respuesta 4a · práctica

La vista actual, en castellano

CREATE VIEW Clientes_Actual AS
SELECT G.Customer_Group_Id       AS Id_Cliente,
       N.CG_Name                 AS Nombre,  -- opcional (con el JOIN)
       G.Start_Dt                AS Fecha_Inicio,
       G.SIC_Cd                  AS Cod_Actividad,
       G.CG_Begin_Dt             AS Fecha_Alta,
       G.Officer_Id              AS Id_Oficial,
       G.Banking_Group_Id        AS Id_Banca,
       G.Telephone_Ind           AS Ind_Telefono,
       G.CG_Type_Cd              AS Cod_Tipo,
       G.Customer_Group_Assoc_Id AS Id_Asociado
FROM CUSTOMER_GROUP G
JOIN CUSTOMER_NAME N ON N.CG_Id = G.Customer_Group_Id
WHERE G.End_Dt = '2100-12-31';

Las tres decisiones

  • “Actual” → End_Dt = '2100-12-31': la foto vigente.
  • “Completa” → todas las columnas, cada una con su AS en castellano.
  • El nombre es opcional: el enunciado no lo pide. Está en CUSTOMER_NAME → JOIN. Sin el JOIN también es válido (la resolución del 12/06/2025 lo hace así): sólo columnas de CUSTOMER_GROUP.

Resultado sobre los datos del examen

Una fila: 125269, Gomez, Juan Carlos, desde 2023-02-02, oficial 978, banca 3.

Ojo

End_Dt se puede omitir en la vista actual: siempre valdría 2100-12-31. En SQL las fechas van como 'AAAA-MM-DD', aunque la tabla del examen las muestre como día/mes/año.

Respuesta 4b · práctica

El indicador: un CASE dentro de la vista

CREATE VIEW Clientes_Actual AS
SELECT G.Customer_Group_Id AS Id_Cliente,
       -- … las mismas columnas de 4a …
       CASE WHEN G.Officer_Id < 21
             AND G.Banking_Group_Id > 4
            THEN 'Externo'
            ELSE 'Propio'
       END AS Ind_Staff
FROM CUSTOMER_GROUP G
JOIN CUSTOMER_NAME N ON N.CG_Id = G.Customer_Group_Id
WHERE G.End_Dt = '2100-12-31';

Cómo leer el enunciado

  • “en la vista anterior” → se agrega a la vista de 4a, no es una consulta aparte.
  • “oficial y banca” → AND: las dos condiciones.
  • “al resto” → ELSE.

Resultado sobre los datos del examen

125269 → Propio: su oficial actual es 978, no es menor a 21.

En criollo

El ejemplo del PPT de BI hace lo mismo con branch = 1. Para practicar con clientes de los dos lados, la lección 0052 tiene tres clientes más inventados: 9946 sale Externo.

Respuesta 4c · práctica

Todos los clientes al 31 de enero de 2021

SELECT *
FROM CUSTOMER_GROUP
WHERE '2021-01-31'
  BETWEEN Start_Dt AND End_Dt;

Por qué así

  • “al 31/01/2021” es estado a una fecha: la foto que cubre ese día.
  • “todos los clientes”: no se filtra por cliente.
  • Se consulta la tabla (o una vista histórica), nunca la vista actual.

Resultado sobre los datos del examen

Una sola foto cumple: la que va del 2/12/2016 al 1/12/2021, con oficial 11.

Ojo

La tabla del examen está en día/mes/año: “1/12/2021” es el 1 de diciembre. Leído como mes/día, pensarías que el 31/01/2021 cae en otra foto.

Respuesta 5a · práctica

“Mayor que la media de los rojos”: una subconsulta escalar

SELECT P.PNOMBRE, P.CIUDAD, E.CANTIDAD
FROM PROVEEDORES P
JOIN ENVIOS E ON E.P = P.P
WHERE E.CANTIDAD > (
  SELECT AVG(E2.CANTIDAD)
  FROM ENVIOS E2
  JOIN COMPONENTES C ON C.C = E2.C
  WHERE C.COLOR = 'ROJO');   -- 400

Cómo se arma

  • La media de los rojos es un solo número: 9 envíos rojos promedian 400.
  • No depende de la fila de afuera: se calcula una vez.
  • “Nombres, ciudad y cantidad” → JOIN con PROVEEDORES.

Respuesta 5b · práctica

“Ambos T1 y T2”: dos condiciones, dos subconsultas

SELECT CNOMBRE, C
FROM COMPONENTES
WHERE C IN (SELECT C FROM ENVIOS WHERE T = 'T1')
  AND C IN (SELECT C FROM ENVIOS WHERE T = 'T2');

Resultado

C4B · C3

La trampa

WHERE T = 'T1' AND T = 'T2' en una sola consulta devuelve vacío (lo probamos): ninguna fila de ENVIOS es de T1 y de T2 a la vez. “Ambos” se resuelve con dos subconsultas, una por artículo.

Respuesta 10a · práctica

“Peso total” = SUM(PESO × CANTIDAD), filtrado con HAVING

SELECT P.PNOMBRE, C.CNOMBRE,
       SUM(C.PESO * E.CANTIDAD) AS Peso_Total
FROM ENVIOS E
JOIN PROVEEDORES P ON P.P = E.P
JOIN COMPONENTES C ON C.C = E.C
GROUP BY P.P, P.PNOMBRE, C.C, C.CNOMBRE
HAVING SUM(C.PESO * E.CANTIDAD) > 20000;

Cómo se arma

  • El peso está en COMPONENTES y la cantidad en ENVIOS → se multiplican por fila y se suman.
  • “Total mayor a” es sobre un agregado → HAVING, no WHERE.

Resultado · una sola fila

JUAN · C4B · 52700

P2 envió 3100 unidades de C3 (peso 17). El siguiente es EVA con 14600: muy lejos.

La trampa del nombre

C3 y C4 se llaman los dos “C4B”. Si agrupás sólo por CNOMBRE, los mezclás (a EVA le suma 3400 + 11200). Agrupá por la clave C.C. Y en SQL Server GROUP BY 1,2 y HAVING Peso_Total (con alias) no andan: repetí la expresión.

Respuesta 10b · práctica

“Ambos T1 y T2”, ahora para proveedores

SELECT PNOMBRE, P
FROM PROVEEDORES
WHERE P IN (SELECT P FROM ENVIOS WHERE T = 'T1')
  AND P IN (SELECT P FROM ENVIOS WHERE T = 'T2');

Resultado

JUAN · P2    JOSE · P3

Dos trampas

WHERE T = 'T1' AND T = 'T2' da vacío, como en la 5b. Y WHERE T IN ('T1','T2') es un OR: devuelve P1, P2, P3 y P5 (lo probamos). “Ambos” = dos subconsultas unidas con AND.
