1 · Slowly Changing Dimensions

Una fila por foto, con fecha de inicio y de fin

  • Tipos: 1 sobrescribe, 2 agrega una fila (guarda historial), 3 agrega una columna.
  • Vigente: la foto actual tiene fecha fin '2100-12-31'.
  • Actual vs. a una fecha: la actual filtra por fecha fin = 2100-12-31. A una fecha se usa BETWEEN, que incluye los extremos.
  • La PK: tiene que ser (cliente_id, fecha_inicio). Si es sólo cliente_id, la segunda foto choca con la primera.
CREATE TABLE CLIENTES (
  cliente_Id            integer,
  Fecha_Inicio_vigencia date,
  Fecha_fin_Vigencia    date,
  banco_Id              smallint,
  Oficial_Id            smallint,
  PRIMARY KEY (cliente_Id, Fecha_Inicio_vigencia)
);

-- Estado al 06/03/2025
SELECT cliente_id, Oficial_Id
FROM   VW_Clientes_Hist
WHERE  '2025-03-06' BETWEEN Fecha_Inicio_vigencia
                      AND Fecha_fin_Vigencia;

1. ¿Qué filtro usás para el estado al 31/12/2021? 2. ¿Por qué falla la PK sólo con cliente_id? — respuestas en la última slide

1 · Slowly Changing Dimensions

La foto anterior y los indicadores con CASE

  • Foto anterior: su fecha fin es la fecha inicio de la actual menos un día. Se busca con un JOIN contra la foto vigente.
  • Cruzá por cliente: si te olvidás c.cliente_id = T.cliente_id, mezclás fotos de clientes distintos.
  • CASE es el IF de SQL: evalúa los WHEN en orden y cierra con END.
  • CorregidoEl alias no es obligatorio. En una vista sí ponelo: sin él la columna se llama como la expresión entera.
-- Foto inmediatamente anterior a la actual
SELECT c.*
FROM   CLIENTES c
INNER JOIN (
    SELECT cliente_id,
           date(Fecha_Inicio_vigencia, '-1 days')
             AS fecha_fin_vig_ant
    FROM   CLIENTES
    WHERE  Fecha_fin_Vigencia = '2100-12-31'
) AS T
  ON  c.cliente_id = T.cliente_id
 AND c.Fecha_fin_Vigencia = T.fecha_fin_vig_ant;

-- Indicador
CASE WHEN banco_id < 200 THEN 'AMBA'
     ELSE 'NO AMBA' END AS Ind_region
Repaso

1. Si la foto actual empieza el 2026-05-25, ¿qué fecha fin tiene la anterior? 2. ¿Qué palabra cierra un CASE?

1 · Slowly Changing Dimensions

Las tres consultas de SCD son el mismo dibujo

A una fecha

WHERE 'X' BETWEEN Start_Dt AND End_Dt: la foto que cubre ese día.

Anterior

JOIN contra la vigente: End_Dt = Start_Dt − 1 día.

Actual

WHERE End_Dt = '2100-12-31': la que no terminó.

Ojo

La fecha del BETWEEN va a la izquierda. Y la fecha abierta es la que traiga la tabla del examen.

2 · Operaciones de conjuntos

Unión, intersección, resta y diferencia simétrica

-- Diferencia simétrica (como la escribió el profe)
SELECT aa.Id_Art
FROM   ARTICULOS_A aa
LEFT OUTER JOIN ARTICULOS_B ab
       ON aa.Id_Art = ab.Id_Art
WHERE  ab.Id_Art IS NULL
UNION
SELECT ab.Id_Art
FROM   ARTICULOS_A aa
RIGHT OUTER JOIN ARTICULOS_B ab
       ON aa.Id_Art = ab.Id_Art
WHERE  aa.Id_Art IS NULL;
Corregido

El PDF ponía cada SELECT entre paréntesis: en SQLite eso es error de sintaxis. Y usaba Id_Art e Id en la misma consulta. Además, el LEFT JOIN no es “idéntico” a EXCEPT: EXCEPT quita duplicados (con Id_Art único da lo mismo).

3 · DDL

DDL define la estructura; DML mueve los datos

  • DDL: CREATE, ALTER, DROP. DML: INSERT, UPDATE, DELETE, SELECT.
  • Restricciones: PRIMARY KEY, FOREIGN KEY, UNIQUE, CHECK (limita los valores que acepta una columna).
  • PK compuesta: sólo a nivel de tabla, en una línea aparte. No se puede escribir junto a una columna.
  • CorregidoEl deck de la cátedra dice no declarar NOT NULL y PRIMARY KEY juntos, porque la PK ya implica NOT NULL. Lo de “Teradata da error” lo inventó NotebookLM. SQLite lo acepta, pero en la hoja seguí al deck.
CREATE TABLE Curso (
  codigo_curso int,
  duracion     int,
  CONSTRAINT pk_curso
    PRIMARY KEY (codigo_curso),
  CONSTRAINT ck_curso_duracion
    CHECK (duracion > 0)
);

ALTER TABLE Curso DROP COLUMN duracion;
ALTER TABLE Curso ADD COLUMN
  saldo decimal(18,4) NOT NULL DEFAULT 0.0;

4 · Stored procedures y triggers

El SP se llama a mano; el trigger se dispara solo

  • Stored procedure: instrucciones guardadas para un proceso (ej. un paso del ETL). Se ejecuta con CALL y recibe parámetros IN/OUT.
  • Trigger: se ejecuta solo ante un INSERT, UPDATE o DELETE. Ve las filas con NEW y OLD.
  • CorregidoPuede ser FOR EACH ROW (una vez por fila) o FOR EACH STATEMENT (una vez por sentencia).
  • INSTEAD OF: reemplaza la operación; se usa para hacer actualizable una vista.
-- SP (sintaxis Teradata, del deck)
CALL Desa_ETL_ADMIN.GET_LOAD_ID('Paquete_A', :Load_id);

-- Trigger
CREATE TRIGGER SueldoTotal1
AFTER INSERT ON EMPLEADO
FOR EACH ROW WHEN (NEW.Dno IS NOT NULL)
BEGIN
  UPDATE DEPARTAMENTO
  SET    SueldoTotal = SueldoTotal + NEW.Sueldo
  WHERE  Dno = NEW.Dno;
END;
Corregido

El PDF omitía BEGIN … END: así no compila. SQLite no tiene stored procedures, por eso el CALL no se puede probar ahí.

5 · Data Warehouse

Inmon arranca por el DW; Kimball, por los data marts

  • Definición (Inmon): datos orientados a temas, integrados, históricos (variantes en el tiempo) y no volátiles.
  • Inmon, top-down: un DW central normalizado (3FN), y de él salen los data marts.
  • CorregidoKimball, bottom-up: data marts en estrella, uno por área. Juntos forman el DW.
  • DW vs. data mart: el DW es corporativo; el data mart es de un área (ej. ventas) y suele estar desnormalizado y resumido.
  • OLTP vs. OLAP: OLTP opera el día a día (CRM, ventas). OLAP analiza la historia (DW).
Repaso

5 · Data Warehouse

Estrella y copo de nieve

Estrella · desnormalizada

Dimensiones con PK simple, sin partir. Menos JOINs, más redundancia.

Copo de nieve · normalizada

Dimensiones partidas en subtablas por FK. Menos espacio, más JOINs.

6 · Transacciones y concurrencia

Todo o nada, y lo que pasa cuando dos se cruzan

  • Atomicidad: se ejecuta toda o nada.
  • Estados: activa → parcialmente confirmada → confirmada (COMMIT). Si algo falla: fallida → abortada (ROLLBACK).
  • Parcialmente confirmada no es segura: terminó su última sentencia, pero si falla antes de grabar el log, se aborta.
  • Actualización perdida: T1 y T2 leen X; T2 escribe encima de lo que escribió T1.
  • Lectura sucia: T2 lee un dato que T1 cambió y todavía no confirmó.
Repaso

1. Si la red cae antes del COMMIT, ¿en qué estado estaba y qué hace el motor? 2. ¿Cómo se llama leer un dato que T1 después abortó?

7 · Seguridad, roles y privilegios

GRANT da, REVOKE quita, y los roles agrupan

  • Control discrecional: el dueño del objeto decide quién accede, con GRANT y REVOKE. El DBA administra cuentas y roles.
  • Rol: un grupo de privilegios. Se le dan permisos al rol y el rol a los usuarios, en vez de uno por uno.
  • WITH GRANT OPTION: el que recibe el permiso puede pasarlo a otros. Sin esa cláusula, no puede.
  • Vistas: para ocultar columnas o filas, se da acceso a una vista y no a la tabla.
-- Lectura a un usuario
GRANT SELECT ON esquema.tabla TO Usuario1;

-- Lectura, y puede pasarla
GRANT SELECT ON esquema.tabla TO Usuario2
WITH GRANT OPTION;

-- Quitar la modificación a un rol
REVOKE UPDATE ON tabla_ventas FROM Rol_A;
Repaso
